# 集成电路创新创业大赛-龙芯中科杯 分区赛决赛暨阶段任务三 评测任务说明

## 项目包说明

本阶段提供两个项目包：

- `ciciec2026_loongson_regional/`：分区赛决赛发布包，以文件形式提供。
- `ciciec_regional_submission_template/`：提交模板仓库，以 Git 仓库形式提供。

`ciciec2026_loongson_regional/` 基于初赛发布包调整而来，部分 RTL 设计文件补充了 `timescale`，DVI 模块中的部分信号定义也进行了调整。发布包同时增加了若干 Python 与 Shell 脚本，用于在 CI/CD 流程中执行 HDL lint、DSP 资源使用检查、WNS 时序检查等合规性检查。（文件形式）

`ciciec_regional_submission_template/` 用于参赛者在指定 GitLab 平台提交设计。CI/CD 流程会将模板仓库中的 RTL 和 SDK 文件合入分区赛决赛发布包，编译 C 程序，并生成 Vivado 工程产物和 bitstream。（Git仓库形式）

发布包提供基础 SoC 作为设计起点。参赛者结合初赛/阶段任务一、二的实现，在此基础上完成矩阵乘法 RTL 计算模块及其软件驱动的增量开发。

## 任务目标

在线 FPGA 实验平台会运行用户仓库 CI/CD 产物中的 `user-sample.bin`。参赛者需要基于发布包中的基础 SoC 增加矩阵乘法 RTL 计算模块，并编写运行在 SoC CPU 上的 C 程序驱动该模块完成计算。

C 程序需要完成以下任务：

1. 从 ExtRAM 读取 5000 组 4x4 无符号矩阵乘法输入数据。
2. 驱动 RTL 矩阵乘法计算模块完成全部矩阵乘法。
3. 将计算结果按规定格式写入 ExtRAM 结果区。
4. 对完整结果区计算 CRC32 校验值。
5. 通过串口输出规定的开始标识、CRC32 校验结果和结束标识。

每组矩阵计算为：

```text
C = A * B
```

其中 `A`、`B`、`C` 均为 4x4 矩阵。`A` 和 `B` 的元素为 32-bit 无符号数，`C` 的每个元素为 4 项 32x32 乘积累加结果，结果宽度为 66 bit。

参赛者至少需要完成两部分内容：

1. RTL 模块：在基础 SoC 上新增或修改 RTL 逻辑，接入至少一个实际承担矩阵乘法计算功能的 RTL 模块，用于完成 4x4 无符号矩阵乘法。
2. C 驱动与校验程序：编写运行在 SoC CPU 上的 C 程序，从 ExtRAM 读取输入数据，驱动 RTL 模块完成计算，将结果写入 ExtRAM 结果区，计算结果区 CRC32，并通过串口输出评测所需标识。

## 关键设计要求

1. RTL 模块可以采用任意与 SoC 兼容的方式接入总线，但设计中必须存在实际承担矩阵乘法计算功能的 RTL 模块。
2. 矩阵乘法任务必须由处理器核（如 OpenLA500）执行 C 程序并驱动 RTL 模块完成，不能仅由 CPU 纯软件循环完成矩阵乘法。
3. SoC 整体设计不允许使用 DSP 资源。
4. WNS（Worst Negative Slack，最差负时序裕量）必须为正值。
5. C 程序编译参数建议写入 Makefile。CI 中的 `COPY_OUTPUT=0` 表示“不拷贝文件”。

## 数据布局

评测脚本会将用户 C 程序编译得到的 `.bin` 文件写入 BaseRAM，并向 ExtRAM 写入矩阵输入数据。ExtRAM 使用小端 32-bit word 布局。

输入区从 ExtRAM 偏移 `0x00000000` 开始。每组输入包含两个 4x4 矩阵 `A` 和 `B`，共 32 个 32-bit 无符号数，占 128 字节。

输入区按 `A0, B0, A1, B1, ...` 的顺序连续存放。第 0 组输入固定为全 0 矩阵，第 1 到第 4999 组输入在每次评测运行时使用随机 seed 生成。5000 组输入区总大小为：

```text
5000 * 128 = 640000 字节 = 0x0009c400 字节
```

结果区紧随输入区之后，起始偏移为 `0x0009c400`。每组结果为一个 4x4 矩阵 `C`，共 16 个 66-bit 无符号结果。每个 `C` 元素拆成 3 个 32-bit word：低 32 位、中 32 位、最高 2 位。每组结果占：

```text
16 * 3 * 4 = 192 字节
```

5000 组结果区总大小为 `960000` 字节。结果区结束偏移为 `0x00186a00`，最后一个有效字节为 `0x001869ff`。

CRC32 的输入数据为完整结果区的字节流，范围为 ExtRAM 偏移 `0x0009c400` 到 `0x001869ff`，长度为 `960000` 字节。CRC32 使用标准 IEEE CRC-32 算法，并按结果区内的小端 word 字节顺序计算。

每个 `C` 元素的存储格式必须为：

```text
C[i][j] word0 = result[31:0]
C[i][j] word1 = result[63:32]
C[i][j] word2 = {30'b0, result[65:64]}
```

第三个 word 只有低 2 位有效。C 程序在计算 CRC32 前也应保证第三个 word 的高 30 位为 0，避免无效 padding 位影响校验结果。

## 硬件实现要求

参赛者必须在基础 SoC 上设计并接入至少一个 RTL 计算模块，用于完成 4x4 无符号矩阵乘法。每个输出元素为 4 项 32x32 乘积累加结果，宽度为 66 bit。

一种可行的接入方式如下：

- 将 `matmul_axi_slave` 作为 AXI slave 外设接入 `soc_top.v` 的 `axiOut_7`。
- 外设地址空间为 `0x1f50_0000`。在 CPU uncached 映射下，C 程序通常使用 `0xbf50_0000` 访问该外设。
- CPU 通过 memory-mapped register 写入 A/B 矩阵、启动计算、轮询完成状态，并读取 C 矩阵结果。
- 若实现 DMA，可扩展 AXI master 主动访问 ExtRAM；若不实现 DMA，可由 CPU 负责在 ExtRAM 与 IP 数据窗口之间搬运数据。

评测不要求必须实现 DMA，也不限定矩阵乘法器的内部微结构。但矩阵乘法计算不能仅作为纯软件循环由 CPU 完成，必须由新增或修改后的 RTL 计算模块参与完成。

示例寄存器接口如下：

| 偏移 | 名称 | 说明 |
|---:|---|---|
| `0x00` | `CTRL` | bit0: start |
| `0x04` | `STATUS` | bit0: busy；bit1: done；bit2: error |
| `0x08` | `SRC_BASE` | 可选，源数据区起始地址 |
| `0x0C` | `DST_BASE` | 可选，结果数据区起始地址 |
| `0x10` | `GROUP_NUM` | 可选，本次连续计算组数 |
| `0x20` ~ `0x5C` | `A_DATA[0..15]` | 矩阵 A 输入窗口 |
| `0x60` ~ `0x9C` | `B_DATA[0..15]` | 矩阵 B 输入窗口 |
| `0xA0` ~ `0x15C` | `C_DATA[0..47]` | 矩阵 C 输出窗口，每个结果占 3 个 word |

## 矩阵乘法器 IP 设计参考

本节只提供矩阵乘法器 IP 的推荐设计方式。评测任务的强制要求仍以本文前述数据布局、输出格式、计时方式和评分规则为准。参赛者可以根据自己的微结构和性能目标调整接口和内部实现，但硬件模块与 C 程序必须协同完成全部 5000 组矩阵乘法任务。

推荐将矩阵乘法器作为 AXI slave 外设接入 SoC，由 CPU 通过 memory-mapped register 方式进行配置、启动和查询。若采用上一节示例寄存器接口，典型的软件流程为：

1. 从 ExtRAM 输入区读取一组 A/B 矩阵。
2. 将 A/B 矩阵按 row-major 顺序写入 `A_DATA[0..15]` 和 `B_DATA[0..15]`。
3. 写 `CTRL.start` 启动硬件计算。
4. 轮询 `STATUS.busy` / `STATUS.done` 等待计算完成。
5. 从 `C_DATA[0..47]` 读取结果。
6. 按评测要求将结果写回 ExtRAM 结果区。

非 DMA 数据窗口方式实现简单，适合优先保证功能正确。矩阵 C 的输出窗口应与结果区格式一致：每个 66-bit 结果使用 3 个 32-bit word 保存，第三个 word 只有低 2 位有效，高 30 位应为 0。

DMA 是可选增强项，不是评测强制要求。若实现 DMA，矩阵乘法器可以额外提供 AXI master 接口，由硬件根据源地址、目标地址和组数主动访问 ExtRAM。此时需要保证 AXI 读写事务完整、可结束，写回结果格式与本文数据布局一致，并且 C 程序与硬件寄存器语义保持一致。

性能优化可以考虑增加硬件内部并行度、减少每组矩阵的寄存器访问次数、使用批量计算控制寄存器减少 CPU 启停开销，或在设计复杂度可控的前提下实现 DMA。优化过程中应持续检查 DSP 使用量是否为 0、WNS 是否为正值、结果高位 padding 是否清零，以及 `MATMUL_DONE` 是否只在结果写回和 CRC32 计算完成后输出。

## C 程序要求

C 程序必须作为硬件模块的驱动与校验程序，完成以下工作：

1. 配置串口输出，波特率为 115200。
2. 在进入矩阵乘法主循环前输出开始标识 `MATMUL_START`。
3. 从 ExtRAM 输入区读取 5000 组 A/B 矩阵。
4. 驱动 RTL 矩阵乘法计算模块完成每组计算，或使用与该模块协同的方式完成计算。
5. 将全部 5000 组结果按规定格式写入 ExtRAM 结果区。
6. 对完整结果区计算标准 IEEE CRC-32。
7. 输出 `MATMUL_CRC32=XXXXXXXX`。
8. 输出结束标识 `MATMUL_DONE`。

发布包或提交模板中的示例程序可能为了本地快速调试，将 `MATMUL_GROUP_NUM` 设置为较小默认值，例如 50。正式评测必须处理 5000 组数据，或在编译参数中显式设置 `MATMUL_GROUP_NUM=5000`。否则结果区长度和 CRC32 都会与评测脚本不一致。

可通过 Makefile 固定正式评测组数，例如：

```makefile
MATMUL_GROUP_NUM ?= 5000
CFLAGS += -DMATMUL_GROUP_NUM=$(MATMUL_GROUP_NUM)
```

评测脚本以串口输出为判定依据。C 程序必须按以下格式输出：

```text
MATMUL_START
MATMUL_CRC32=XXXXXXXX
MATMUL_DONE
```

其中 `XXXXXXXX` 为 8 位十六进制 CRC32，可以使用大写或小写字母，不带 `0x` 前缀。

输出要求如下：

- 实际输出至少包含 `MATMUL_START\n`、`MATMUL_CRC32=XXXXXXXX\n` 和 `MATMUL_DONE\n`。
- `MATMUL_START`、`MATMUL_CRC32=` 和 `MATMUL_DONE` 必须完全一致，区分大小写。
- 标识字符串前后不得添加空格。
- 单个标识不得拆成多段输出。
- 可以输出其他调试信息，但不得改变 `MATMUL_START`、`MATMUL_CRC32=XXXXXXXX`、`MATMUL_DONE` 的相对顺序。
- 如果输出多个不同的 `MATMUL_CRC32` 值，评测将判定为失败。
- 必须在所有结果已写入 ExtRAM 且 CRC32 已计算完成后，再输出 `MATMUL_DONE`。

## 自动评测流程

评测脚本按以下流程运行：

1. 保持 SoC 处于复位状态。
2. 生成 5000 组 4x4 无符号矩阵乘法测试数据，其中非 0 组每次运行随机生成。
3. 在评测脚本内计算期望结果区 CRC32。
4. 向 BaseRAM 写入 `user-sample.bin`。
5. 向 ExtRAM 写入初始矩阵数据。
6. 配置并打开串口，波特率为 115200。
7. 释放复位。
8. 等待串口输出 `MATMUL_START`，收到后开始计时。
9. 解析串口输出中的 `MATMUL_CRC32=XXXXXXXX`。
10. 等待串口输出 `MATMUL_DONE`，收到后立即停止计时。
11. 比对用户程序输出的 CRC32 与评测脚本计算的期望 CRC32。
12. 输出 CRC32 正确性、elapsed time 和得分。

计时只覆盖 `MATMUL_START` 到 `MATMUL_DONE` 之间的时间，不从释放复位时开始计时。释放复位后等待 `MATMUL_START` 的超时时间为 12 秒；收到 `MATMUL_START` 后等待 `MATMUL_DONE` 的超时时间为 25 秒。收到 `MATMUL_DONE` 后，评测脚本会立即停止计时并结束评测，不会继续等待后续输出。

评测脚本总运行时间上限为 25 秒。

## 评测得分

如果在远程 FPGA 实验平台测试中遇到 `SysErr`，可能是系统或平台问题，请联系管理员。

以下情况得 0 分：

- 超时。
- 缺少 `MATMUL_START`、`MATMUL_CRC32=XXXXXXXX` 或 `MATMUL_DONE`。
- `MATMUL_DONE` 出现在 `MATMUL_START` 之前。
- CRC32 格式错误。
- 输出多个不一致的 CRC32。
- 用户程序输出的 CRC32 与评测脚本计算的期望 CRC32 不匹配。

CRC32 校验通过后，至少得 20 分，并按运行时间获得性能分。评分配置如下：

- CRC32 通过基础分：20 分。
- 性能分：80 分。
- `elapsed_ms <= 5`：100 分。
- `elapsed_ms >= 10000`：20 分。
- `10 < elapsed_ms < 10000`：在 100 分到 20 分之间按对数曲线映射。

评分公式为：

```text
ratio = (ln(10000) - ln(elapsed_ms)) / (ln(10000) - ln(5))
score_percent = 20 + 80 * ratio
```

评测日志会记录随机 seed、expected CRC32、reported CRC32、elapsed time 和 score percent，便于复现与定位问题。

## 评测产物来源说明

在线 FPGA 实验平台执行本评测任务时，需要同时使用 CI/CD 产物中的 bitstream 和与其对应的 `user-sample.bin`。评测脚本会将该 `user-sample.bin` 写入 BaseRAM，并使用同一份 CI/CD 产物中的 bitstream 配置 FPGA。

因此，本评测任务不能使用本地 Vivado 生成的 bitstream 进行在线测试。原因是本地提交入口只允许上传 bitstream，无法同时提交与该 bitstream 配套的 `user-sample.bin`；而本任务的评测逻辑必须依赖 C 程序二进制文件协同运行。参赛者应通过 `ciciec_regional_submission_template/` 仓库触发 CI/CD 流程，并使用 CI/CD 生成的完整产物进行在线评测。

## 相对初赛发布包的主要变化

与初赛发布包 `ciciec2026_loongson_preliminary/` 相比，分区赛决赛发布包 `ciciec2026_loongson_regional/` 的主要变化集中在评测任务、辅助工具和 CI/CD 约束上。参赛者如果基于初赛工程继续开发，应注意以下事项。

1. 评测任务从初赛内容调整为矩阵乘法任务。

   分区赛决赛评测要求参赛者完成 5000 组 4x4 无符号矩阵乘法，并按规定结果区格式写回 ExtRAM、计算 CRC32、通过串口输出评测标识。参赛者需要围绕本说明文档中的数据布局、输出格式和评分规则进行设计，而不是沿用初赛评测任务。

2. 发布包提供矩阵乘法测试数据生成辅助脚本。

   `tools/generate_matmul_testdata.py` 用于生成矩阵乘法输入数据和期望结果数据，便于参赛者在本地调试数据布局、结果格式和 CRC32 计算逻辑。本地生成的数据只用于调试和复现，正式在线评测仍以平台评测脚本运行时生成的数据为准。

3. C 程序正式评测组数固定为 5000。

   本地调试时可以使用较小的数据组数以缩短仿真时间；正式 CI/CD 流程会通过命令行显式传入 `MATMUL_GROUP_NUM=5000`。参赛者应确保 C 程序、Makefile 和本地仿真参数之间保持一致，并保证正式评测时处理完整 5000 组输入。

4. BSP 编译流程增加 `COPY_OUTPUT` 开关。

   分区赛发布包的 `sdk/software/bsp/common.mk` 增加了 `COPY_OUTPUT ?= 1`。当 CI 使用 `COPY_OUTPUT=0` 编译时，只保留当前编译目录下的产物，不再将 `.bin`、`.mif` 等文件复制到发布包其他位置。该参数不表示评测组数，也不影响 C 程序逻辑；矩阵组数应通过 `MATMUL_GROUP_NUM` 控制。

5. FPGA 流程增加 CI 合规检查脚本。

   分区赛发布包新增了 `fpga/run_impl.tcl`、`fpga/generate_bit.tcl`、`fpga/run-linter.py`、`fpga/check_dsp.py` 和 `fpga/check_timing.py`。CI/CD 会使用这些脚本执行 Vivado 实现、生成 bitstream、检查 HDL lint、检查 DSP 使用量以及检查 WNS。参赛者需要特别注意：设计中不允许使用 DSP 资源，且实现后的 WNS 必须为正值。

6. 部分 RTL 文件做了工程适配性修改。

   分区赛发布包在若干 RTL 文件中补充了 `timescale`，并对部分模块声明做了适配调整，用于提高仿真、lint 和综合流程的一致性。其中 DVI 模块的部分 AXI 输出信号在模块内部由时序逻辑赋值，因此端口声明需使用寄存器型输出，以避免 Verilog 下出现对 wire 型 output 进行过程赋值的问题。参赛者迁移初赛设计时通常不需要回退这些工程适配性修改。

7. 本地仿真与在线评测的使用方式不同。

   发布包中的测试数据生成脚本可用于本地调试矩阵乘法流程，但在线 FPGA 实验平台的正式评测只使用 CI/CD 产物。由于在线评测需要 bitstream 与对应的 `user-sample.bin` 协同运行，不能直接使用本地 Vivado 生成的 bitstream 进行本任务评测。

8. 迁移初赛工程时应保留分区赛发布包的新增基础设施。

   如果参赛者从初赛工程迁移已有设计，不建议直接用初赛目录整体覆盖分区赛发布包。应只迁移相对发布包新增或修改的 CPU、外设、驱动等源码，并保留分区赛发布包中的 CI 检查脚本、SDK 构建逻辑和矩阵乘法测试数据布局。否则可能导致 CI 无法生成正确产物，或在线评测无法找到匹配的 bitstream 与 `user-sample.bin`。
